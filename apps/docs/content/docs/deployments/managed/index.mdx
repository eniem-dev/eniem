## Prerequisites

Before you begin, make sure you have:

- Your project running locally without errors
- A [GitHub](https://github.com) account
- A [Vercel](https://vercel.com) account

---

## Step 1: Create a GitHub Repository

Create a new repository on GitHub to host your project code.

<img src="/images/deployments/managed/1.png" alt="Create a new repository on GitHub" />

1. Go to [github.com/new](https://github.com/new)
2. Enter a repository name
3. Choose **Private** visibility
4. Click **Create repository**

Then push your local code to the repository:

```bash
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin git@github.com:your-username/your-repo.git
git push -u origin main
```

---

## Step 2: Create Vercel Project

Create a new project on Vercel and link it to your GitHub repository.

<img src="/images/deployments/managed/2.png" alt="Create new project on Vercel" />

1. Go to [vercel.com/new](https://vercel.com/new)
2. Search for your repository in the **Import Git Repository** section
3. If your repository doesn't appear, click **Configure GitHub App**

<img src="/images/deployments/managed/3.png" alt="Grant repository access to Vercel" />

4. Select **Only select repositories** and choose your repository
5. Save the configuration

### Configure Environment Variables

<img src="/images/deployments/managed/4.png" alt="Environment variables configuration" />

Add your environment variables by clicking **Import .env** or adding them manually.

> **Important:** Do NOT include `DATABASE_URL` in your environment variables. This will be added automatically when you link the Prisma database in the next steps.

Click **Deploy** to start the first deployment.

---

## Step 3: Create Prisma Database

Create a Prisma Postgres database from the Vercel Marketplace.

<img src="/images/deployments/managed/5.png" alt="Prisma on Vercel Marketplace" />

1. Go to [Vercel Marketplace](https://vercel.com/marketplace) and search for **Prisma**
2. Click **Install** on the Prisma integration

<img src="/images/deployments/managed/6.png" alt="Create Database modal" />

3. Select the **Region** closest to your users
4. Choose your **Plan** (Free tier includes 5 databases, 100K operations/month, 500MB storage)
5. Click **Continue** to create the database

---

## Step 4: Link Database to Project

Connect your Prisma database to your Vercel project.

<img src="/images/deployments/managed/7.png" alt="Connect Vercel project" />

1. After creating the database, click **Connect Project**
2. Select your Vercel project from the list
3. Confirm the connection

<img src="/images/deployments/managed/8.png" alt="Database dashboard with connection strings" />

The database dashboard shows your connection strings. Click **Show secret** to reveal them.

### Run Migrations

After linking the database, you need to run migrations to create your tables:

1. Copy the `DATABASE_URL` from the Prisma dashboard
2. Set it in your local `.env` file temporarily:

```bash
DATABASE_URL="postgresql://..."
```

3. Run the migration command:

```bash
pnpm db:migrate
```

## Post-Deployment

### Update Environment URLs

After deployment, update the URL-related environment variables in Vercel with your production URLs:

- `NEXT_PUBLIC_APP_URL` → `https://your-app.vercel.app`
- `BETTER_AUTH_URL` → `https://your-app.vercel.app`
- Any other URL-based variables

> **Tip:** If you configure a custom domain from the start, you can skip this step.

### Prisma Commands Reference

| Command               | What it does (short)                             | Typical context / when to use                     |
| --------------------- | ------------------------------------------------ | ------------------------------------------------- |
| prisma generate       | Regenerates Prisma Client from schema.prisma     | After editing schema or Prisma config             |
| prisma migrate dev    | Creates & applies a new migration in dev         | While developing features locally                 |
| prisma migrate deploy | Applies existing migrations to prod/staging      | On deploy (CI/CD, production/staging)             |
| prisma migrate reset  | Drops and recreates dev DB, reapplies migrations | When dev DB is dirty; start from clean slate      |
| prisma db push        | Syncs schema to DB with NO migration files       | Early prototyping / throwaway dev DB only         |
| prisma studio         | Opens web UI to browse/edit data                 | Inspect or manually tweak data during development |
