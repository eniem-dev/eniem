## Error Classes

Custom error classes in `src/lib/errors.ts` provide typed errors with HTTP status codes.

| Class               | Status Code | Default Message       |
| ------------------- | ----------- | --------------------- |
| `ServerError`       | 500         | custom message        |
| `UnauthorizedError` | 401         | `"Unauthorized"`     |
| `ValidationError`   | 400         | `"Validation failed"` |

```ts
export class ServerError extends Error {
  constructor(message: string, public statusCode: number = 500) {
    super(message);
    this.name = "ServerError";
  }
}

export class UnauthorizedError extends ServerError {
  constructor(message: string = "Unauthorized") {
    super(message, 401);
    this.name = "UnauthorizedError";
  }
}

export class ValidationError extends ServerError {
  constructor(message: string = "Validation failed") {
    super(message, 400);
    this.name = "ValidationError";
  }
}
```

## Server-Side Error Handling

`classifyError` in `src/lib/handler.ts` converts thrown errors into response metadata for queries, actions, and routes.

### Error Processing Order

1. **UnauthorizedError** → 401, logged as warning
2. **ValidationError** → 400, logged as warning
3. **ServerError** → custom status code, logged as error
4. **ZodError** → 400, first issue message extracted, logged as warning
5. **Generic Error** → 500, logged as error with stack trace
6. **Unknown** → 500, uses `locales.errors.unhandledError`, logged as error

Expected client-side failures (401/400) are warnings. Unexpected server failures are errors.

### Response Formats

**Server Queries** (`authed.query`, `publicly.query`):

```ts
type Result<T> =
  | { data: T; error: null }
  | { data: null; error: string };
```

**API Routes** (`authed.route`, `publicly.route`):

```ts
type ApiResponse<T> =
  | { success: true; data: T }
  | { success: false; error: string };
```

## Error Boundary

The `app/error.tsx` component catches runtime errors in the React tree and displays a user-friendly error page. The `reset()` function re-renders the route segment, allowing recovery from transient errors.

```tsx
"use client";

export default function Error({ reset }: { reset: () => void }) {
  return (
    <main>
      <h1>{locales.ErrorPage.title}</h1>
      <p>{locales.ErrorPage.description}</p>
      <button onClick={() => reset()}>{locales.ErrorPage.tryAgain}</button>
      <Link href="/">{locales.ErrorPage.backToHome}</Link>
    </main>
  );
}
```

## Usage

### Throwing Errors in Handlers

Throw custom errors inside handlers or services. Request-boundary wrappers catch and classify them.

```ts
import { ServerError, ValidationError } from "@/lib/errors";
import { authed } from "@/lib/handler";
import { getResourceForUser } from "../services/resource.service";

export const getResource = () =>
  authed.query(async ({ user }) => {
    const resource = await getResourceForUser(user.id);

    if (!resource) {
      throw new ServerError("Resource not found", 404);
    }

    if (!resource.isValid) {
      throw new ValidationError("Resource is invalid");
    }

    return resource;
  });
```

### Handling Responses

Both server queries and API handlers return discriminated unions. Check the discriminator before accessing data.

```ts
import { logger } from "@/lib/logger";

const result = await getResource();
if (result.error) {
  logger.warn("Unable to load resource", { error: result.error });
  return;
}

const resource = result.data;
```

```ts
const response = await fetch("/api/resource");
const json = await response.json();

if (!json.success) {
  toast.error(json.error);
  return;
}

const resource = json.data;
```

### Server Actions

Server actions using next-safe-action return `serverError` and `validationErrors`.

```ts
import { logger } from "@/lib/logger";

const result = await updateProfileAction({ name: "John" });

if (result?.serverError) {
  toast.error(result.serverError);
  return;
}

if (result?.validationErrors) {
  logger.warn("Profile validation failed", { validationErrors: result.validationErrors });
  return;
}

const data = result?.data;
```

With the `useAction` hook:

```tsx
const { execute, isPending } = useAction(updateProfileAction, {
  onSuccess: () => {
    toast.success("Updated!");
  },
  onError: ({ error }) => {
    toast.error(error.serverError ?? "Something went wrong");
  },
});
```

### Type Guards

Use the provided type guards for cleaner TypeScript narrowing.

```ts
import { logger } from "@/lib/logger";
import { isActionSuccessful } from "@/lib/safe-action";

const actionResult = await subscribeAction({ email: "user@example.com" });
if (isActionSuccessful(actionResult)) {
  logger.info("Subscribe action completed", { id: actionResult.data?.id });
}
```

### resolveActionResult

`resolveActionResult` converts an action result into a Promise that resolves with data or rejects with the server error message.

```ts
import { resolveActionResult } from "@/lib/safe-action";

try {
  const data = await resolveActionResult(
    subscribeAction({ email: "user@example.com" })
  );
  // use data
} catch (error) {
  toast.error(String(error));
}
```
