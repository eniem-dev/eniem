The email system provides a universal `sendEmail` dispatcher for server-side code. It accepts a discriminated `EmailMessage` union, renders the matching React Email template, logs in development, and sends through Resend in production.

## Why This Architecture?

- **Type-safe message shapes** - Each email type declares exactly the data it needs
- **Provider independence** - Swap Resend for another provider by changing the dispatcher
- **React components as templates** - Type-safe, composable, and easy to maintain
- **Development mode debugging** - Emails are logged with tokens/OTPs for local testing
- **Boundary-specific behavior** - Callers decide whether a failed `EmailResult` should throw, retry, or show a user-facing error

## Overview

| File | Purpose |
| --- | --- |
| `src/lib/email/send-email.ts` | Low-level email dispatcher |
| `src/lib/email/types.ts` | `EmailMessage` and `EmailResult` discriminated unions |
| `src/lib/email/resend-client.ts` | Resend client factory |
| `src/lib/auth/email-hooks.ts` | BetterAuth email callbacks that adapt auth events to `EmailMessage` |
| `src/components/emails/` | React Email templates |
| `src/components/emails/components/EmailLayout.tsx` | Shared layout wrapper |

## The sendEmail Dispatcher

```ts
import { sendEmail } from "@/lib/email/send-email";
import type { EmailMessage, EmailResult } from "@/lib/email/types";

const message: EmailMessage = {
  type: "verification",
  to: "user@example.com",
  data: {
    token: "token-value",
    url: "https://app.example.com/verify?token=token-value",
  },
};

const result: EmailResult = await sendEmail(message);

if (!result.success) {
  // Decide at the boundary whether to throw, retry, or surface the error.
}
```

### Message Types

```ts
export type EmailMessage =
  | { type: "otp"; to: string; data: { otp: string } }
  | { type: "verification"; to: string; data: { url: string; token: string } }
  | { type: "password-reset"; to: string; data: { url: string; token: string } }
  | { type: "delete-account"; to: string; data: { url: string; token: string } };

export type EmailResult =
  | { success: true }
  | { success: false; error: { code: "send_failed"; message: string } };
```

## How It Works

In development, emails are rendered to plain text and logged:

```ts
logger.info("email.dev", {
  to: msg.to,
  type: msg.type,
  subject,
  ...debugInfo,
  body: text,
});
```

In production, emails are sent via Resend:

```ts
const { error } = await getResend().emails.send({
  from: env.email.fromAddress,
  to: msg.to,
  subject,
  react: template,
});

return error
  ? { success: false, error: { code: "send_failed", message: error.message } }
  : { success: true };
```

## BetterAuth Integration

BetterAuth callbacks live in `src/lib/auth/email-hooks.ts`. They convert auth events into typed email messages:

```ts
import { sendEmail } from "@/lib/email/send-email";

type UserEmailType = "password-reset" | "verification" | "delete-account";

async function sendUserEmail(
  type: UserEmailType,
  { user, url, token }: UserUrlToken
) {
  await sendEmail({ type, to: user.email, data: { url, token } });
}

export const sendResetPassword = (p: UserUrlToken) =>
  sendUserEmail("password-reset", p);

export const sendVerificationEmail = (p: UserUrlToken) =>
  sendUserEmail("verification", p);

export async function sendOtp({ email, otp }: { email: string; otp: string }) {
  await sendEmail({ type: "otp", to: email, data: { otp } });
}
```

## Using sendEmail in Application Code

For custom emails, extend the `EmailMessage` union and `renderMessage` switch in `src/lib/email/send-email.ts`, then call `sendEmail` from server-side code.

```ts
"use server";

import { sendEmail } from "@/lib/email/send-email";

export async function sendVerificationReminder(email: string, token: string, url: string) {
  const result = await sendEmail({
    type: "verification",
    to: email,
    data: { token, url },
  });

  if (!result.success) {
    return { success: false, error: result.error.message };
  }

  return { success: true };
}
```

## React Email Templates

Templates are React components using `@react-email/components` for email-client compatibility.

### EmailLayout Component

All templates use a shared layout for consistency:

```tsx
interface EmailLayoutProps {
  preview: string;
  brandLogoUrl?: string;
  children: React.ReactNode;
}

export function EmailLayout({ preview, brandLogoUrl, children }: EmailLayoutProps) {
  return (
    <Html>
      <Head />
      <Preview>{preview}</Preview>
      <Body style={main}>
        <Container style={container}>
          {brandLogoUrl && <Img src={brandLogoUrl} alt="Logo" />}
          {children}
        </Container>
      </Body>
    </Html>
  );
}
```

### Template Example

```tsx
interface OtpEmailProps {
  otp: string;
  expiresInSeconds: number;
  brandLogoUrl?: string;
}

export function OtpEmail({ otp, expiresInSeconds, brandLogoUrl }: OtpEmailProps) {
  return (
    <EmailLayout
      preview={`Your verification code is ${otp}`}
      brandLogoUrl={brandLogoUrl}
    >
      <Text>Your verification code</Text>
      <Section>
        <Text>{otp}</Text>
      </Section>
      <Text>This code expires in {formatExpiryTime(expiresInSeconds)}.</Text>
    </EmailLayout>
  );
}
```

## Creating Custom Templates

1. Create the React Email component in `src/components/emails/`
2. Export it from `src/components/emails/index.ts`
3. Add a new variant to `EmailMessage` in `src/lib/email/types.ts`
4. Add a matching case to `renderMessage()` in `src/lib/email/send-email.ts`
5. Call `sendEmail` from your server action, route, background job, or service

## Swapping Email Providers

The dispatcher keeps provider-specific code isolated. To switch providers, update the production branch of `sendEmail` in `src/lib/email/send-email.ts`. The message union, templates, and auth hooks stay the same.

## Configuration

Set these environment variables:

```bash
RESEND_API_KEY=re_xxxxxxxxxxxxx
EMAIL_FROM_ADDRESS=no-reply@yourdomain.com
EMAIL_BRAND_LOGO_URL=https://yourdomain.com/logo.png
```

Configuration is centralized in `src/config/env.ts`:

```ts
email: {
  resendApiKey: process.env.RESEND_API_KEY,
  fromAddress: process.env.EMAIL_FROM_ADDRESS || "no-reply@eniem.dev",
  brandLogoUrl: process.env.EMAIL_BRAND_LOGO_URL,
}
```

## Best Practices

1. Keep `sendEmail` as the low-level dispatcher.
2. Put boundary behavior in the caller: auth hooks, actions, routes, or jobs decide how to handle `{ success: false }`.
3. Do not leak tokens/OTPs in production logs.
4. Keep email styles inline for broad email client support.
5. Test in development first; `sendEmail` logs the rendered plain-text body and debug fields.
