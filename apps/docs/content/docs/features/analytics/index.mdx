## Why This Architecture?

The analytics abstraction provides several key benefits:

- **Built-in Provider Toggle** - Switch between Umami, PostHog, or disable analytics via a single environment variable
- **Provider Independence** - Same `captureEvent` API regardless of which provider you use
- **Simple API** - One function to learn: `captureEvent(name, properties)`
- **Type Safety** - Full TypeScript support for event properties
- **Lazy Loading** - Providers are loaded only when needed
- **Easy Testing** - Mock the abstraction for tests without provider complexity

## Quick Start

Set your preferred provider in `.env`:

```bash
# Umami (default) - lightweight, privacy-focused
NEXT_PUBLIC_ANALYTICS_PROVIDER=umami

# PostHog - feature-rich with session replay, funnels, A/B tests
NEXT_PUBLIC_ANALYTICS_PROVIDER=posthog

# Disable analytics
NEXT_PUBLIC_ANALYTICS_PROVIDER=none
```

## Provider Configuration

### Umami (Default)

Umami is a lightweight, privacy-focused analytics solution. It's the default provider.

```bash
NEXT_PUBLIC_ANALYTICS_PROVIDER=umami
NEXT_PUBLIC_UMAMI_WEBSITE_ID=your-website-id
NEXT_PUBLIC_UMAMI_HOST=https://cloud.umami.is
```

Get your Website ID from your [Umami dashboard](https://cloud.umami.is/).

### PostHog

PostHog provides feature-rich product analytics including session replay, funnels, and A/B testing.

```bash
NEXT_PUBLIC_ANALYTICS_PROVIDER=posthog
NEXT_PUBLIC_POSTHOG_KEY=phc_your_project_key
NEXT_PUBLIC_POSTHOG_HOST=https://eu.posthog.com
```

Get your key from your [PostHog project settings](https://app.posthog.com/project/settings).

PostHog is initialized with these options:

| Option | Description |
| --- | --- |
| `api_host` | Proxy endpoint for events (avoids ad blockers) |
| `ui_host` | PostHog dashboard URL (EU or US) |
| `capture_exceptions` | Enable automatic error tracking |
| `debug` | Log events to console in development |

### Disable Analytics

To completely disable analytics (useful for development or self-hosted instances):

```bash
NEXT_PUBLIC_ANALYTICS_PROVIDER=none
```

## The Tracking Abstraction

The core of the analytics system is a provider-agnostic abstraction in `lib/tracking.ts`:

```ts
import { getAnalyticsProvider } from "@/lib/analytics";

export function captureEvent(eventName: string, properties?: Record<string, unknown>) {
  const provider = getAnalyticsProvider();
  provider.capture(eventName, properties);
}
```

The `getAnalyticsProvider()` function lazily loads the configured provider, ensuring that:
- Only the selected provider's code is loaded
- Missing configuration is logged as warnings
- The API remains consistent regardless of provider

## Usage

### Basic Event Tracking

```tsx
import { captureEvent } from "@/lib/tracking";

export function SignUpButton() {
  const handleClick = () => {
    captureEvent("signup_button_clicked");
  };

  return <button onClick={handleClick}>Sign Up</button>;
}
```

### Events with Properties

```tsx
import { captureEvent } from "@/lib/tracking";

export function PricingCard({ plan }: { plan: string }) {
  const handleSelect = () => {
    captureEvent("plan_selected", {
      plan_name: plan,
      page: "pricing",
    });
  };

  return <button onClick={handleSelect}>Select {plan}</button>;
}
```

### Form Submission Tracking

```tsx
import { captureEvent } from "@/lib/tracking";
import { useAction } from "next-safe-action/hooks";

export function NewsletterForm() {
  const [email, setEmail] = useState("");

  const { execute, isExecuting } = useAction(subscribeAction, {
    onSuccess: ({ data }) => {
      captureEvent("email_submitted", { email });
      toast.success(data.message);
    },
  });

  return (
    <form action={() => execute({ email })}>
      <input value={email} onChange={(e) => setEmail(e.target.value)} />
      <button type="submit" disabled={isExecuting}>Subscribe</button>
    </form>
  );
}
```

## Event Naming Conventions

Use `snake_case` for event names and be consistent:

| Event | Description |
| --- | --- |
| `page_viewed` | User viewed a page |
| `button_clicked` | User clicked a button |
| `form_submitted` | User submitted a form |
| `signup_completed` | User completed signup |
| `purchase_completed` | User completed a purchase |

## Adding Custom Providers

To add a new provider (e.g., Google Analytics, Mixpanel):

1. Create a new provider file in `lib/analytics/`:

```ts
// lib/analytics/mixpanel.ts
import type { AnalyticsProvider } from "./types";
import mixpanel from "mixpanel-browser";

export const mixpanelProvider: AnalyticsProvider = {
  capture: (eventName, properties) => {
    mixpanel.track(eventName, properties);
  },
};
```

2. Update `lib/analytics/index.ts` to include your provider:

```ts
case "mixpanel":
  return mixpanelProvider;
```

3. Add the new option to your environment configuration.

## Best Practices

1. **Always use the abstraction** - Never import provider SDKs directly in components
2. **Consistent naming** - Establish event naming conventions early and document them
3. **Track user intent** - Focus on meaningful actions, not every click
4. **Avoid PII** - Don't track personal identifiable information unless necessary
5. **Check configuration** - Missing env vars are logged as warnings, check your console
