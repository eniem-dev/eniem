## Philosophy

### Middleware-First Approach

We rely on middleware as much as possible for access control. This centralizes security in `src/middleware.ts` and prevents individual pages from forgetting authentication checks.

### Private by Default

Pages are protected by default. Only explicitly whitelisted routes in `PUBLIC_ROUTES` or `PUBLIC_ROUTE_PREFIXES` are accessible without authentication.

This means:

- If you forget to add a route to `PUBLIC_ROUTES`, it stays protected
- You avoid the unsafe public-by-default failure mode

## Access Levels Overview

| Level         | Requirement                    | Redirect       | Example Routes             |
| ------------- | ------------------------------ | -------------- | -------------------------- |
| **Public**    | None                           | -              | `/`, `/pricing`, `/blog/*` |
| **Protected** | Logged in                      | `/login`       | `/account/*`               |
| **Access**    | Logged in + Subscription/Order | `/choose-plan` | `/dashboard/*`             |

## Public Pages

Public pages are defined in `src/middleware.ts`:

```ts
const PUBLIC_ROUTES = [
  routes.home,
  routes.homeRedirect,
  routes.pricing,
  routes.auth.signup,
  routes.auth.login,
  routes.auth.forgotPassword,
  routes.auth.resetPassword,
  routes.legal.termsOfService,
  routes.legal.privacy,
];

const PUBLIC_ROUTE_PREFIXES = [routes.blog];
const AUTH_API_PREFIX = "/api/auth";
```

The middleware also allows all routes under `/api/auth/*` for BetterAuth.

## Protected Pages

Protected pages require a valid BetterAuth session. If no session is found, the user is redirected to `/login`.

```ts
import { auth } from "@/lib/auth/config";

async function handleAuthentication(request: NextRequest): Promise<NextResponse> {
  const { pathname } = request.nextUrl;

  const isPublicRoute =
    PUBLIC_ROUTES.includes(pathname) ||
    PUBLIC_ROUTE_PREFIXES.some(
      (prefix) => pathname === prefix || pathname.startsWith(`${prefix}/`)
    ) ||
    pathname.startsWith(AUTH_API_PREFIX);

  if (isPublicRoute) return NextResponse.next();

  const session = await auth.api.getSession({ headers: await headers() });

  if (!session) {
    return NextResponse.redirect(new URL(routes.auth.login, request.url));
  }

  const accessResponse = await handleAccess(request, session.user.id);
  if (accessResponse) return accessResponse;

  return NextResponse.next();
}
```

## Access Required Pages

Some pages require authentication plus either an active subscription or a one-time purchase. If the user is logged in but lacks access, they are redirected to `/choose-plan`.

```ts
import { hasActiveSubscription } from "@/features/billing";
import { hasActiveOrder } from "@/features/benefits";

const REQUIRE_ACCESS_ROUTES: string[] = [routes.dashboard];

async function handleAccess(
  request: NextRequest,
  userId: string
): Promise<NextResponse | null> {
  const { pathname } = request.nextUrl;

  const requiresAccess = REQUIRE_ACCESS_ROUTES.some(
    (route) => pathname === route || pathname.startsWith(`${route}/`)
  );

  if (!requiresAccess) return null;

  // Choose ONE based on your business model:
  const hasUserAccess = await hasActiveSubscription(userId);
  // const hasUserAccess = await hasActiveOrder(userId);
  // const hasUserAccess = await hasActiveSubscription(userId) || await hasActiveOrder(userId);

  return hasUserAccess
    ? null
    : NextResponse.redirect(new URL(routes.choosePlan, request.url));
}
```

## Utility Functions

### Server Utilities

For authentication inside queries, actions, and API routes, use `authed` and `publicly` from `@/lib/handler`.

See [Server Utilities](/features/server-utilities) for detailed documentation.

### Access Functions

#### Subscription Check

Located in `features/billing/services/subscription.service.ts` and exported from `@/features/billing`:

```ts
import { hasActiveSubscription } from "@/features/billing";

const isActive = await hasActiveSubscription(userId);
```

`hasActiveSubscription(userId)` returns `Promise<boolean>` and checks the locally synced subscription status.

#### One-Time Purchase Check

Located in `features/benefits/services/benefits.service.ts` and exported from `@/features/benefits`:

```ts
import { hasActiveOrder } from "@/features/benefits";

const hasOrder = await hasActiveOrder(userId);
```

`hasActiveOrder(userId)` returns `Promise<boolean>` and checks Polar benefit grants through the `PolarGateway`. It works for GitHub repository access and downloadable files.

## Usage Examples

### Creating a Protected Page

Middleware handles protection, but a page may still need session data for rendering:

```tsx
// app/(protected)/account/general/page.tsx
import { ErrorCard } from "@/components/error-card";
import { auth } from "@/lib/auth/config";
import { locales } from "@/locales";
import { headers } from "next/headers";

export default async function AccountPage() {
  const session = await auth.api.getSession({ headers: await headers() });

  if (!session) {
    return <ErrorCard message={locales.errors.unauthorized} />;
  }

  return <div>Welcome, {session.user.name}</div>;
}
```

### Using Authenticated Query

```ts
import { authed } from "@/lib/handler";
import { getUserProfile } from "../services/user.service";

export const getUserQuery = () =>
  authed.query(async ({ user }) => {
    return getUserProfile(user.id);
  });
```

### Using Authenticated Server Action

```ts
"use server";

import { authed } from "@/lib/handler";
import { updateProfile } from "../services/profile.service";
import { updateProfileSchema } from "./schemas";

export const updateProfileAction = authed
  .input(updateProfileSchema)
  .action(async ({ input, user }) => {
    await updateProfile(user.id, input);
    return { success: true };
  });
```
