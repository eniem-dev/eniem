## Architecture

Subscription state now lives inside the consolidated billing feature:

```
features/billing/
├── index.ts                         # Public billing API exports
├── generated/
│   ├── products.generated.ts        # CLI-generated checkout/pricing products
│   └── meters.generated.ts          # CLI-generated usage meters
├── models/
│   └── subscription.model.ts        # Subscription domain types
├── queries/
│   ├── billing-overview.query.ts    # Authenticated overview query
│   └── subscription.query.ts        # Authenticated subscription query
└── services/
    └── subscription.service.ts      # Sync + active-subscription checks
```

The BetterAuth Polar plugin is wired in `src/lib/auth/plugins/polar.ts`. Auth lifecycle and webhook side-effects are centralized in `src/lib/auth/side-effects.ts`, which delegates subscription sync to the billing feature.

## Database Model

Subscriptions are stored locally for fast access in middleware and server components.

**File:** `prisma/schema.prisma`

```prisma
model Subscription {
  id                  String    @id @default(cuid())

  // Polar identifiers
  polarSubscriptionId String    @unique
  polarProductId      String

  // Status
  status              String    // "active", "canceled", "past_due", "trialing"
  recurringInterval   String    // "year" or "month"

  // Billing cycle
  currentPeriodStart  DateTime
  currentPeriodEnd    DateTime
  cancelAtPeriodEnd   Boolean   @default(false)
  canceledAt          DateTime?
  startedAt           DateTime

  // Amounts (stored in cents)
  amount              Int
  currency            String    @default("usd")

  // Timestamps
  createdAt           DateTime  @default(now())
  updatedAt           DateTime  @updatedAt

  // Relation: One user has one subscription
  userId              String    @unique
  user                User      @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

## Product Configuration

Products are managed by the CLI and generated into `src/features/billing/generated/products.generated.ts`. The checkout plugin receives the generated checkout products for the active Polar environment:

```typescript
import { env } from "@/config";
import { getCheckoutProducts } from "@/features/billing/generated/products.generated";

checkout({
  products: getCheckoutProducts(env.payment.polarServer),
  successUrl: "/success?checkout_id={CHECKOUT_ID}",
  authenticatedUsersOnly: true,
});
```

Use the [CLI Products Command](/guides/cli) to add, sync, and regenerate products instead of manually listing product IDs in auth config.

## Webhook Configuration

1. Go to **Polar Dashboard → Organization Settings → Webhooks**
2. Add webhook URL: `https://yourdomain.com/api/auth/polar/webhooks`
3. Copy the webhook secret to `POLAR_WEBHOOK_SECRET`

Webhooks are handled by the BetterAuth Polar plugin in `src/lib/auth/plugins/polar.ts`:

```typescript
webhooks({
  secret: env.payment.polarWebhookSecret,
  onCustomerStateChanged,
  onOrderPaid: async (payload) => {
    logger.info("Polar: Order paid", {
      orderId: payload.data.id,
      userId: payload.data.customer?.externalId,
      product: payload.data.product.name,
    });
  },
  onPayload: async (payload) => {
    logger.info("Polar: Webhook received", { payload });
  },
});
```

`onCustomerStateChanged` delegates to `onPolarCustomerStateChanged`, which calls `syncSubscription(userId, activeSubscriptions)` through the billing server API.

## Sync Mechanism

### Primary: Webhook Sync

**File:** `features/billing/services/subscription.service.ts`

```typescript
export async function syncSubscription(userId: string, activeSubscriptions: PolarSubscription[]) {
  if (activeSubscriptions.length > 0) {
    const sub = activeSubscriptions[0];
    // Upsert the local subscription record from Polar state.
    // Missing required dates are logged and ignored.
    return;
  }

  await deleteSubscription(userId);
}
```

The service is the only place that writes subscription rows. Queries, actions, and route handlers should call services instead of using Prisma directly.

### Secondary: Post-Checkout Sync

Webhooks are asynchronous. After checkout, the success page proactively fetches current customer state through the Polar gateway and syncs the local subscription before redirecting the user:

```typescript
import { syncSubscriptionFromPolar } from "@/features/billing";

await syncSubscriptionFromPolar(session.user.id);
```

Internally, `syncSubscriptionFromPolar(userId)` calls `polar.fetchActiveSubscriptions(userId)` and then reuses `syncSubscription()`.

## Public Billing APIs

### Check Active Status

```typescript
import { hasActiveSubscription } from "@/features/billing";

const isActive = await hasActiveSubscription(userId);
```

### Server Component Query

For billing pages, use the authenticated overview query:

```tsx
import { BillingOverview, getBillingOverviewQuery } from "@/features/billing";
import { ErrorCard } from "@/components/error-card";

export default async function BillingPage() {
  const { data, error } = await getBillingOverviewQuery();

  if (error || !data) {
    return <ErrorCard message={error ?? "Unable to load billing"} />;
  }

  return <BillingOverview data={data} />;
}
```

## Route Protection

Protect routes that require paid access using middleware. Choose the model that matches your product:

```typescript
import { hasActiveSubscription } from "@/features/billing";
import { hasActiveOrder } from "@/features/benefits";

// Subscription-only
const hasUserAccess = await hasActiveSubscription(userId);

// One-time purchase
// const hasUserAccess = await hasActiveOrder(userId);

// Hybrid
// const hasUserAccess = await hasActiveSubscription(userId) || await hasActiveOrder(userId);
```

Users without access are redirected to the pricing/choose-plan page.

## Customer Portal

Let users manage their subscription through Polar's hosted portal:

```typescript
import { authClient } from "@/lib/auth-client";

await authClient.customer.portal();
```

The portal plugin is configured in `src/lib/auth/plugins/polar.ts`.
