## Configuration

### Environment Variables

Configure your DigitalOcean Spaces connection in `.env`:

| Variable                                | Description                           | Example                                                  |
| --------------------------------------- | ------------------------------------- | -------------------------------------------------------- |
| `DIGITALOCEAN_SPACES_ENDPOINT`          | Region endpoint (without bucket name) | `https://ams3.digitaloceanspaces.com`                    |
| `DIGITALOCEAN_SPACES_REGION`            | Region code                           | `ams3`                                                   |
| `DIGITALOCEAN_SPACES_BUCKET`            | Your bucket name                      | `my-app-uploads`                                         |
| `DIGITALOCEAN_SPACES_ACCESS_KEY_ID`     | Spaces access key                     | `DO00...`                                                |
| `DIGITALOCEAN_SPACES_SECRET_ACCESS_KEY` | Spaces secret key                     | `...`                                                    |
| `DIGITALOCEAN_SPACES_CDN`               | CDN URL for public access             | `https://my-app-uploads.ams3.cdn.digitaloceanspaces.com` |
| `MAX_FILE_SIZE_MB`                      | Maximum upload size in MB             | `1`                                                      |

### DigitalOcean Setup

1. **Create a Space** in the [DigitalOcean console](https://cloud.digitalocean.com/spaces)
2. **Enable CDN** (recommended) for faster file delivery
3. **Generate API keys** in Settings → API → Spaces Keys
4. **Configure CORS** if uploading directly from browser (optional)

## Architecture

### Storage Path Organization

Files are organized by environment and user to prevent mixing production data with development:

```
{BUCKET}/
├── prod/
│   └── users/
│       └── {userId}/
│           └── {timestamp}-{filename}
└── no-prod/
    └── users/
        └── {userId}/
            └── {timestamp}-{filename}
```

### File Naming

Files are renamed with a timestamp prefix and sanitized:

- Original: `My Photo (1).jpg`
- Stored as: `1699876543210-My_Photo__1_.jpg`

This ensures uniqueness and prevents path traversal issues.

## Usage

### Upload Utility

The core upload function in `lib/file-upload.ts`:

```ts
import { uploadImage } from "@/lib/file-upload";

// Upload a file and get the public CDN URL
const imageUrl = await uploadImage(file, userId);
// Returns: https://bucket.ams3.cdn.digitaloceanspaces.com/prod/users/user-123/1699876543210-photo.jpg
```

### Validation Schema

Define file validation with Zod in your feature's schema file:

```ts
// features/settings/settings.schemas.ts
import { z } from "zod";
import { env } from "@/config";
import { locales } from "@/locales";

export const updateImageSchema = () =>
  z.object({
    image: z
      .any()
      .refine((file) => {
        if (!file || file.size === 0) return false;
        return file.type?.startsWith("image/");
      }, locales.errors.fileRequired)
      .refine((file) => file.size <= env.upload.maxFileSizeBytes, {
        message: locales.errors.fileTooLarge,
      }),
  });
```

### Server Action

Create an authenticated action for secure uploads:

```ts
// features/settings/settings.action.ts
"use server";

import { authenticatedActionClient } from "@/lib/safe-action.server";
import { updateImageSchema } from "./settings.schemas";
import { uploadImage } from "@/lib/file-upload";
import { logger } from "@/lib/logger";
import { locales } from "@/locales";

export const updateImageAction = authenticatedActionClient
  .inputSchema(updateImageSchema())
  .action(async ({ parsedInput, ctx }) => {
    const { image } = parsedInput;
    const { session } = ctx;

    logger.info("Starting image upload", {
      userId: session.user.id,
      fileSize: image.size,
    });

    const imageUrl = await uploadImage(image, session.user.id);

    return { imageUrl };
  });
```

### Client Component

Integrate uploads in your React components:

```tsx
"use client";

import { useAction } from "next-safe-action/hooks";
import { updateImageAction } from "@/features/settings";
import { env } from "@/config";
import { locales } from "@/locales";
import { toast } from "sonner";

export function ImageUpload() {
  const { execute, isPending } = useAction(updateImageAction, {
    onSuccess: ({ data }) => {
      if (data?.imageUrl) {
        toast.success("Image uploaded!");
      }
    },
    onError: ({ error }) => {
      toast.error(error.serverError ?? "Upload failed");
    },
  });

  const handleFileChange = async (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0];
    if (!file) return;

    // Client-side validation
    if (file.size > env.upload.maxFileSizeBytes) {
      toast.error(locales.errors.fileTooLarge);
      return;
    }

    if (!file.type.startsWith("image/")) {
      toast.error(locales.errors.invalidFileType);
      return;
    }

    // Upload
    execute({ image: file });
  };

  return (
    <input
      type="file"
      accept="image/*"
      onChange={handleFileChange}
      disabled={isPending}
    />
  );
}
```

## Best Practices

### 1. Validate on Both Sides

Always validate file type and size on both client and server:

```ts
// Client: Fast feedback, better UX
if (file.size > env.upload.maxFileSizeBytes) {
  toast.error("File too large");
  return;
}

// Server: Security enforcement via Zod schema
.refine((file) => file.size <= env.upload.maxFileSizeBytes, ...)
```

### 2. Use the Logger

Log upload operations for debugging and monitoring:

```ts
logger.info("Starting upload", { userId, fileSize, fileType });
logger.error("Upload failed", { userId, error: error.message });
```

### 3. Handle Errors Gracefully

Use localized error messages from the `locales` file:

```ts
// locales/index.ts
errors: {
  fileRequired: "Please select an image file",
  fileTooLarge: "Image exceeds maximum file size",
  fileUploadFailed: "Failed to upload file. Please try again.",
}
```

### 4. Leverage the CDN

Always use the CDN URL (configured via `DIGITALOCEAN_SPACES_CDN`) for serving files. The upload utility automatically returns CDN URLs.

## Security

| Aspect                     | Implementation                                            |
| -------------------------- | --------------------------------------------------------- |
| **ACL**                    | Files use `public-read` ACL (suitable for profile images) |
| **Environment Separation** | `prod/` and `no-prod/` folders prevent data mixing        |
| **User Isolation**         | Files stored in user-specific folders                     |
| **Filename Sanitization**  | Special characters removed, timestamp added               |
| **Authentication**         | Server action requires authenticated session              |
