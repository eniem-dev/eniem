---
title: "Landing Mode"
description: "Landing mode is a feature that allows you to create a basic landing page to collect emails while you are building your application."
---

The purpose is while this mode is enabled to redirect all requests to the landing page.

All the code related to the newsletter feature is located in the folder `features/newsletter`.

## Setup

First to enable landing mode you should set the environment variable `LANDING_MODE` to `true`.

```bash
LANDING_MODE=true
```

## Middleware

When the landing mode is enabled the Next.js middleware will redirect all requests to the landing page except the pages that are whitelisted.

**middleware.ts**

```ts
const LANDING_MODE_ALLOWED_ROUTES = [
  routes.landing,
  routes.legal.termsOfService,
  routes.legal.privacy,
];
```

```ts
function handleLandingMode(request: NextRequest): NextResponse | null {
  if (!env.landingMode) return null;

  const { pathname } = request.nextUrl;

  const isAllowedRoute = LANDING_MODE_ALLOWED_ROUTES.includes(pathname);
  return isAllowedRoute
    ? NextResponse.next()
    : NextResponse.redirect(new URL(routes.landing, request.url));
}
```

This way when a user tries to access any page of the application they will be redirected to the landing page.

## Collecting Emails

The newsletter feature provides two methods for collecting emails through a service layer.

### Service Layer

The service layer (`features/newsletter/services/newsletter.service.ts`) provides two functions:

```ts
import { prisma } from "@/lib/db";
import { addContact } from "@/lib/email";
import { logger } from "@/lib/logger";

// Method 1: Save to database
export async function saveEmailToDatabase(email: string): Promise<void> {
  await prisma.collectedEmail.create({ data: { email } });
  logger.info("Email saved to database", { email });
}

// Method 2: Save to email provider (Resend)
export async function saveEmailToProvider(email: string): Promise<void> {
  await addContact(email);
  logger.info("Email saved to email provider", { email });
}
```

### Method 1: Database Storage (Default)

By default, the newsletter action saves collected emails to the database using the `CollectedEmail` model:

```prisma
model CollectedEmail {
  id        String   @id @default(cuid())
  email     String   @unique
  createdAt DateTime @default(now())

  @@map("collected_emails")
}
```

This is useful when you want to:
- Keep full control over your email list
- Export emails manually later
- Use your own email marketing solution

### Method 2: Email Provider (Resend)

The second method sends emails directly to your email provider (Resend) using the `addContact` function from `lib/email.ts`.

This is useful when you want to:
- Automatically add subscribers to your Resend audience
- Use Resend's built-in email marketing features
- Sync contacts in real-time

### Switching Between Methods

Edit the action file at `features/newsletter/actions/newsletter.action.ts`:

```ts
export const subscribeToNewsletterAction = actionClient
  .inputSchema(newsletterSchema)
  .action(async ({ parsedInput: { email } }) => {
    try {
      logger.info("Collecting email for newsletter", { email });

      // Method 1: Save to database (default)
      await saveEmailToDatabase(email);

      // Method 2: Save to email provider (Resend)
      // Uncomment to send emails to your email marketing provider
      // await saveEmailToProvider(email);

      logger.info("Email collected successfully", { email });
      return { success: true, message: locales.LandingPage.newsletter.success };
    } catch (error: unknown) {
      // ... error handling
    }
  });
```

To use the email provider method:
1. Comment out `await saveEmailToDatabase(email);`
2. Uncomment `await saveEmailToProvider(email);`

You can also use both methods simultaneously to have a local backup while syncing with your email provider.
