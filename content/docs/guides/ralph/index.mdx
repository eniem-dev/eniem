Ralph is an autonomous AI coding workflow that uses Claude Code to implement features from specifications. It follows a spec-driven approach: define requirements in `specs/`, generate an implementation plan, then let Claude build iteratively.

## Setup

Make the loop script executable after cloning:

```bash
chmod +x loop.sh
```

## How It Works

1. **Create specs** via `/spec-interview` or manually in `specs/*.md`
2. **Plan** analyzes specs and generates `IMPLEMENTATION_PLAN.md`
3. **Build** implements tasks one at a time, validates, commits, and loops

```
specs/*.md → plan → IMPLEMENTATION_PLAN.md → build → committed code
```

## Quick Start

```bash
# 1. Create a spec for your feature
/spec-interview user-authentication

# 2. Generate implementation plan (scoped to your feature)
pnpm ralph:plan-work "user authentication"

# 3. Build iteratively (1 iteration, supervised)
pnpm ralph:build

# 4. Or run autonomously (10 iterations)
pnpm ralph:build:auto
```

## Commands

| Command | Description |
| ------- | ----------- |
| `pnpm ralph:plan` | Full planning from all specs |
| `pnpm ralph:plan-work "desc"` | Scoped planning for specific work |
| `pnpm ralph:build` | Single build iteration (supervised) |
| `pnpm ralph:build:auto` | 10 build iterations (autonomous) |

## Modes

### Plan Mode

Analyzes all specs and generates a prioritized implementation plan:

```bash
pnpm ralph:plan
# or with interactive output
./loop.sh plan -i
```

Uses `PROMPT_plan.md` to:
- Study specs with parallel Sonnet subagents
- Perform gap analysis against existing code
- Generate `IMPLEMENTATION_PLAN.md` with prioritized tasks

### Work-Scoped Plan Mode

Creates a focused plan for specific work:

```bash
pnpm ralph:plan-work "user authentication"
# or
./loop.sh plan-work "user authentication" -i
```

Uses `PROMPT_plan_work.md` to:
- Focus only on specs relevant to the scope
- Generate a plan with branch creation as first task
- Include PR creation as final task

### Build Mode

Implements tasks from the plan one at a time:

```bash
# Single iteration (supervised)
pnpm ralph:build

# Multiple iterations (autonomous)
./loop.sh build 10

# Interactive mode (watch Claude work)
./loop.sh build 5 -i
```

Uses `PROMPT_build.md` to:
1. Select the most important task from the plan
2. Search codebase to verify it doesn't already exist
3. Implement using parallel Sonnet subagents
4. Validate (build, lint, tests must pass)
5. Update plan and commit
6. Exit for fresh context on next iteration

## Creating Specs

### Via Interview

Use the `/spec-interview` command for guided spec creation:

```bash
/spec-interview analytics-dashboard
```

The interview covers:
1. **Purpose & JTBD**: What job does this feature accomplish?
2. **Target User**: Who uses this feature?
3. **Scope**: What's included and excluded?
4. **Requirements**: Must-have vs nice-to-have
5. **Constraints**: Technical and performance limits
6. **Acceptance Criteria**: Testable success conditions
7. **Edge Cases**: Error states and boundaries

Output is saved to `specs/<feature-name>.md`.

### Manual Spec Format

Create specs manually in `specs/`:

```markdown
# Feature Name

## Overview
One paragraph summary of the feature and its purpose.

## Job to Be Done
What user need this addresses.

## Target User
Who uses this feature.

## Requirements

### Must Have
- [ ] Requirement 1
- [ ] Requirement 2

### Nice to Have
- [ ] Optional requirement

## Constraints
- Technical constraint
- Performance requirement

## Acceptance Criteria
- [ ] Specific, testable criterion 1
- [ ] Specific, testable criterion 2

## Edge Cases
- Edge case 1: expected behavior
- Edge case 2: expected behavior

## Out of Scope
- Thing explicitly not included
```

## Claude Commands

### `/spec-interview`

Interactive spec creation through guided questions:

```bash
/spec-interview <feature-name>
```

### `/fix-code-review`

Automatically address GitHub PR review comments:

```bash
/fix-code-review https://github.com/owner/repo/pull/123
```

Process:
1. Fetches review comments from the PR
2. Analyzes and proposes fixes
3. Shows plan for approval
4. Applies approved fixes
5. Validates (build, lint, tests)
6. Detects pattern gaps for CLAUDE.md updates

## Guardrails

Ralph follows strict guardrails (9-series numbering for priority):

- **Single sources of truth** - No migrations or backwards compatibility adapters
- **Search before implementing** - Never assume functionality is missing
- **One task per iteration** - Fresh context prevents drift
- **Validation required** - Never commit failing code
- **Follow existing patterns** - CLAUDE.md conventions over new ones
- **WHY over WHAT** - Documentation captures reasoning

## Workflow Example

```bash
# 1. Interview for new feature
/spec-interview user-dashboard

# 2. Plan the implementation
pnpm ralph:plan-work "user dashboard"

# 3. Review the generated plan
cat IMPLEMENTATION_PLAN.md

# 4. Build iteratively
pnpm ralph:build      # Run once, review
pnpm ralph:build      # Run again
pnpm ralph:build:auto # Or let it run autonomously

# 5. PR is created automatically as final task
```
